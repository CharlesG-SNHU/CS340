**CS-340 Client/Server Development**

Writing maintainable and adaptable code came down to one decision made early in Project One: building the CRUD operations as a standalone Python module rather than embedding database logic directly in the dashboard. That separation meant the dashboard code never needed to know anything about how MongoDB was being queried. When filter requirements changed between projects, the dashboard widgets stayed untouched and only the module needed updating. The same CRUD module could be dropped into any other Python application that needs to talk to MongoDB, a data pipeline, a REST API, or a different dashboard framework entirely, without rewriting the database logic from scratch.

Approaching this project as a computer scientist meant starting with the client's actual requirements before touching any code. Grazioso Salvare needed to filter animals by rescue type and surface actionable information quickly. That meant the database schema, the indexes, and the dashboard layout all had to be designed around those specific queries rather than around what was easiest to build. This differed from most coursework where the problem is already fully defined. Here the requirement was to translate a real operational need into a technical solution, which meant making judgment calls about what data to expose and how to structure the aggregation. Going forward I would apply the same approach to any client database project: start with the queries the client actually needs to run, then design the schema to support those queries efficiently.

Computer scientists turn raw data into tools that help people make better decisions faster. For a company like Grazioso Salvare, the difference between a spreadsheet and a filtered interactive dashboard is the difference between manually scanning hundreds of animal records and identifying the right rescue candidates in seconds. That kind of tooling directly affects how effectively their teams operate in the field. The work matters because the end user is not evaluating code quality, they are trying to do a job, and well-designed software either gets out of their way or it does not.
